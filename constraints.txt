# constraints.txt — fully-pinned transitive closure for reproducible installs.
#
# WHY: razor_rooster declares lower-bound-only deps (e.g. numpy>=1.26) with no
# lockfile. CI ran `pip install -e ".[dev]"` and re-resolved to the latest
# release every run. On 2026-06-24 main went red twice in one sitting from this
# drift: unpinned numpy pulled PEP-695 stubs mypy rejected, then a fastapi/
# starlette bump stopped flattening included routes and broke a GUI test. This
# file pins the ENTIRE closure (runtime + dev tooling + transitive) to a snapshot
# verified green: 3092 tests passed, ruff clean, mypy --strict CB gate clean.
#
# APPLY: pip install -e ".[dev]" -c constraints.txt  (see Makefile `install`).
# A constraints file only pins versions of packages that get installed; it does
# not itself install anything. razor_rooster (-e .) and sloptropy-common
# (git+ssh, pinned @cb841a4 in CI) are editable/VCS installs and are
# deliberately ABSENT here — constraints cannot pin a URL/editable requirement.
#
# REGENERATE after an intentional dependency change (see Makefile `upgrade`/`lock`):
#   make upgrade && make lock     # re-resolve, re-verify gates, then refreeze
# NOT hash-pinned (no --require-hashes): the failure class was version drift, and
# --require-hashes is incompatible with the editable + git-VCS installs above.
#
# Snapshot: 2026-06-25 | Python 3.12 | source: pip freeze --exclude-editable
